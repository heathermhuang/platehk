## Operational notes

- Auto-update behavior right now:
  - [scripts/cron_update.sh](../scripts/cron_update.sh) now runs [scripts/build_events.py](../scripts/build_events.py).
  - That script fetches the two TD overview pages, regenerates [data/events.json](../data/events.json), then the normal update pipeline can publish the refreshed JSON with the site.
  - The homepage loads `./data/events.json` at runtime and the service worker treats it as network-first data, so deployed users should see refreshed event data after the update job and deployment have run.
  - No separate external scheduler or auto-deploy rule was created in this change; the site is only as fresh as the existing cron/deploy process that runs `scripts/cron_update.sh`.
- The current in-app browser is on `file://<repo>/index.html`. Browser `file://` mode usually cannot fetch `./data/events.json`, so it will show the fallback PVRM registration item only. Use local HTTP or the deployed site to see all four feed-backed event items.
- The live production site is [https://plate.hk/](https://plate.hk/). The in-app browser may still be looking at the local `file://` copy unless manually navigated.
- The PVRM registration event is generated from the recurring January/May/September application-window rule. Auction and E-Auction events are scraped from the TD overview pages.
- Broad `git status --short --untracked-files=all` was slow/hung in this repo because of the generated/untracked surface. Explicit path checks were used instead.
- Production Playwright verification saw a Google Analytics CSP warning for `https://www.google.com/g/collect`. This appears unrelated to the homepage UI release; current Worker CSP allows Google Analytics domains but not `www.google.com` in `connect-src`.
